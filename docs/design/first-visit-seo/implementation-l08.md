## Перед разрешённым выпуском

1. Обновить Git refs без изменения рабочей копии; сверить и сохранить согласованный набор исходников. Игнорируемые docs/артефакты не входят автоматически в Git. Назначить версию и проверить именно сохранённый кандидат в CI. Тестовые web-образы L07 с фиктивной конфигурацией не публиковать.
2. До API release получить свежий зашифрованный защищённый dump, проверить archive listing и восстановление на отдельной БД. Проверка размера текущей БД: 9 942 707 bytes; дамп/восстановление в L08 не выполнялись. Отдельно сохранить Caddyfile с metadata и Compose. Старые резервные копии не считать свежими. Каталог backups внутри deploy directory при проверке не обнаружен; место защищённого хранения ещё не назначено.
3. Сохранить доступность предыдущих immutable web/API/migrator артефактов и соответствующего Compose: release workflow выполняет prune. Наличие работающих образов не доказывает будущую доступность в registry.
4. Только после отдельного разрешения опубликовать приложение. Проверить новый API shim с новым web shell и index.html до изменения Caddy.
5. Для Caddy: повторно сверить исходный checksum/active JSON; сделать защищённую резервную копию. Кандидат проверить тем же установленным бинарником. Файл смонтирован отдельным bind mount: при установке/откате сохранять inode существующего файла, не заменять его через `mv`.
6. После отдельного согласования Caddy применить файл и вызвать точную команду: `docker exec caddy-caddy-1 caddy reload --config /etc/caddy/Caddyfile --adapter caddyfile`. Применять только если текущий контейнер/mount/конфигурация всё ещё совпадают с проверенными.
7. При откате Caddy восстановить подтверждённый снимок в тот же файл с прежними owner/mode/inode, validate, затем эту же reload-команду. Отдельно откатывать приложение на совместимые сохранённые артефакты. Реальный путь серверного backup и команды его восстановления фиксируются после создания; восстановление БД в production для проверки запрещено.
8. Проверить основной домен без JS, canonical/robots/sitemap XML, static/private GET/HEAD, health и owner mobile smoke. Поисковые аккаунты, отправка sitemap и метрики идут после live-приёмки при отдельном доступе.

Фактические backup, Git commit/push/tag, app deploy, Caddy apply/reload, DNS и действия в поисковых аккаунтах остаются невыполненными. Кандидат готов к рассмотрению; полный выпуск L08 не объявляется завершённым.
