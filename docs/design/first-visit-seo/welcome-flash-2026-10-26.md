# Welcome: вспышка при повторном открытии главной

26 октября 2026. Владелец сообщил о кратком показе welcome при заходе/обновлении главной и отдельно согласовал исправление. На момент работы production — v1.4.0 / b3b0a37. Исправление только локальное; commit/push/release пока не выполнялись.

## Причина

После включения Caddy API отдаёт реальный welcome в начальном HTML для всех запросов главной. Существующая загрузочная поверхность заменялась целиком. Проверка localStorage/#map выполнялась только после загрузки приложения: React убирал уже успевший появиться welcome у повторного посетителя.

## Изменение

- Синхронный inline script в head выбирает начальную поверхность до разбора body. Он компилируется при сборке из той же firstVisitPolicy, которую использует React; ключ и значение acknowledgement находятся там же. Второй независимый набор правил показа не вводился. Новых зависимостей/HTTP-запросов нет. Размер inline script: 680 bytes.
- API сохраняет исходную bootstrap-поверхность с прежним logo URL рядом с публичным welcome. Критические inline styles при подтверждённом посещении/#map показывают только loader. Скрипт не запускает карту и не ждёт авторизацию.
- Первый визит, #intro и review mode остаются в welcome, #map сохраняет приоритет. Ошибка доступа к localStorage не ломает первый визит. Без JavaScript welcome и два описания доступны.
- Ранний CSS ограничен начальными server wrappers. После замены root он не скрывает повторно открываемый React welcome. Тексты SEO, карта/drawer и условия завершения посещения не менялись.

## Проверки

- RED: 8 регрессионных проверок выявили отсутствие раннего выбора и потерю loader. Затем 46 focused checks прошли.
- Все пять обязательных проверок прошли: оба tsc, lint, style boundaries, 185 client/server файлов / 1687 тестов. Использован прежний --maxWorkers=4, утверждения и лимиты не ослаблялись.
- Scripts: 5 файлов / 63 теста прошли. Web/API build и прежние bundle budgets прошли. `git diff --check` прошёл.
- Проверен фактический built index.html после server injection: 8 вариантов URL/посещения/storage, стили начальных поверхностей, сохранённый logo asset, отсутствие влияния на повторное открытие и читаемость без JS. Это Node/jsdom simulation, не измерение первого кадра физическим браузером.
- В тесте потребовалось уточнить тип варианта Vite HTML hook; затем все проверки повторены успешно. Правила TypeScript/lint не ослаблялись.

Логи: `.scratch/first-visit-flash/`; checks.json, scripts.log, build.log, budgets.log, built-parity.json. Отпечатки исходников: source-files.json. Браузер/dev server/visual suite не запускались по CLAUDE.md §6.

## Публикация и приёмка

Для реального дефекта нужна выдача API shim через основной домен; обычный Vite localhost без server injection не воспроизводит этот начальный HTML. При разрешении выпустить вместе web/API как v1.4.1, после CI и стандартной проверки backup/provenance. Изменение Caddy не требуется.

На опубликованном исправлении владелец проверяет:
1. Открыть /#intro, выбрать Find my photos и дождаться карты. Затем открыть / и обновить её: welcome не должен кратко появляться перед картой; допустим обычный loader до готовности приложения.
2. Открыть /#intro повторно: welcome должен показываться. При первом визите в новом браузерном профиле он также должен оставаться видимым.

Наличие исходного HTML и автоматические проверки не выдаются за подтверждение отсутствия визуального моргания на устройстве. Production до отдельно одобренного выпуска продолжает работать на v1.4.0.

## Разрешение на выпуск

Владелец отдельно разрешил сохранить исправление в Git и выпустить v1.4.1 после CI. Caddy остаётся без изменений. Дальнейшие результаты публикации фиксируются отдельным отчётом.
